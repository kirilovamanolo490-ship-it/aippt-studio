# 可执行的场景排版基线

新建演示时，Studio 先判断用途与受众，再把所选场景的版面参数写进 `deck-plan.json` 的 `planning_strategy.visual_style_profile`。HTML 制作链直接使用这些参数设置整页边距、标题/正文层级、行高、元素间隔及图文比例；原生 PptxGenJS 制作链在对象没有明确字号时，按 `cover_title`、`title`、`body`、`caption` 角色使用相应字号。每个文字对象的明确 `fontSize` 优先。两条制作链仍需检查真实整页，而不是仅凭参数宣称美观。

表中尺寸采用 Studio 16:9、1920 × 1080 的制作画布；对应 13⅓ × 7½ 英寸幻灯片时约 **2 画布像素 = 1 磅**。边距和间隔均为画布像素。它们是该场景首稿的可执行起点，不是所有作品的最低字号法则。来源 PPT、给定参考、品牌/母版、用户明确指定的字体或构图优先；`template_relayout`、`local_patch` 等来源保留任务不自动套用新稿基线。
原生场景若明确使用另一页幅，字号角色按页宽和页高相对 16:9 基准的较小比例缩放，避免大画布沿用小屏字号；真实页面仍须检查。字体家族优先使用任务/场景明确选择，其次才是场景候选和宿主字体回退。

字体也按场景分成标题、正文和标签三种角色。当前 Mac 字体清单确认可用的中文字体包括 `Hiragino Sans GB`、`Heiti SC` 和 `Songti SC`；同时确认 `Avenir Next`、`Chalkboard SE`、`Arial Rounded MT Bold`、`DIN Alternate` 等拉丁字体。候选栈先放中文字体，再放拉丁辅助字体：CSS 可逐字使用后备字体；原生 PowerPoint 对象每个对象只能绑定一个字体名，Studio 选用候选栈首个中文字体，英文字符仍可能由 Office 回退，因此仍需在目标 PowerPoint 中检查中英混排和实际字形。Windows 候选依次回退到 `Microsoft YaHei UI`、`Microsoft YaHei`、`Arial`；Linux 候选为 `Noto Sans CJK SC`、`WenQuanYi Micro Hei`、`Noto Sans`。

Mac 角色组合按场景区分：通用使用 Hiragino Sans GB；政务标题使用 Heiti SC、正文使用 Hiragino Sans GB；商务标题以 Hiragino Sans GB 为主并回退到 Avenir Next；竞赛与技术标题以 Heiti SC 为主；学术标题使用 Songti SC；教学标题使用 Hiragino Sans GB 并回退到 Chalkboard SE；儿童标题使用 Hiragino Sans GB 并回退到 Arial Rounded MT Bold；仪式叙事标题使用 Songti SC 并回退到 Avenir Next；作品集标题及正文使用 Songti SC 并回退到 Avenir Next/Hiragino Sans GB。标签优先采用相应中文字体，数字和拉丁字符再落到 DIN Alternate、Avenir Next 或 Arial。

字体优先次序为：文字对象显式 `options.fontFace` → 原生场景显式 `font_family` → 非默认 `DeckPlan.font_family` → 新稿场景的标题/正文/标签候选 → 宿主默认字体。若字体字段仍为系统默认值（Mac 的 `PingFang SC` 或 Windows 的 `Microsoft YaHei`），它表示旧版默认值，不压过新稿场景配置。参考稿、母版和现有作品中的字体安排继续优先于这些候选。原生场景若没有 `style_role`，Studio 只根据已批准的 `SlideSpec.title` 标出标题对象；其余文字仍用正文角色。表格继承正文面孔和字号，图表标签使用图注尺度，但对象显式选项优先。

### 典藏合集需求词如何落到场景基线

文件夹名不是演讲场合。面试/个人介绍若以真实作品和项目为核心，可借“品牌及作品集”的图片证据与编辑层级；若只需简短资历说明，先用通用叙事。招聘/招新应先围绕岗位、职责、条件和报名行动组织，不因 `C021` 的颜色或插画固定成某一种风格。商业计划面对投资人时常需业务决策的结论与数据关系，面对竞赛评委时则需竞赛答辩的问题、创新与可行性链。科技内容讲机制时用技术说明，产品发布面对公众时可按仪式叙事组织开场，但性能和边界仍用真实证据。工作总结区分内部经营复盘与党政机构汇报；前者参考业务决策，后者按正式机构的事实、责任和时序组织。销售方案按购买决策与商品真实性安排，不能因目录中有“销售趋势图”就把数据图当整稿模板。

模板分类目录直接位于 `模板库/` 下；先通过 `模板库/CATALOG.jsonl` 按任务和页面功能检索，再把候选的主题/母版/单页关系与上述基线、当前受众和来源内容比较。完成案例按实际用途归类，其逐页表达观察位于 `模板库/EXPRESSION-EXAMPLES.json`，只作表达参考。

场景还决定页级语法。HTML 场景中的概览页和事实页在政务、商业、竞赛、研究、教学、技术、叙事、作品集下使用不同网格与分组关系；封面、图文页、证据页和结论页按消息内容选择，不要求每一页照搬同一张模板。突出陈述与图注也分别使用场景的 statement 和 caption 尺度；两者受整页布局控制，不单独追求极端大小。原生场景只应用字号和字体角色默认值；`grammar`、图文比例和图片框/适配记录为规划参考，不自动改写原生对象位置或图片几何，避免覆盖作者明确设置。图片默认完整显示并保持自身轮廓；要裁切、蒙版或圆角时，必须让图片和外框成为同一几何处理，不能把直角图片硬塞进独立的椭圆或圆角底框。无意义角标序号和工程性旁白不属于场景基线。

选择边界：只有 `NEW_COMPOSITION + CREATE_NEW` 会把这些数值应用到制作链。其他模式仍可在计划中看到相应场景作为审阅参考，但应忠实于当前来源。儿童基线只在受众信息明确指向低龄学习者时选用，不根据图片颜色或单个“可爱”词推断。若正文放不下，应先改写页面信息结构、拆分证据或换版式，再决定是否微调字号；不能单纯缩小文字来让自动检查变绿。
