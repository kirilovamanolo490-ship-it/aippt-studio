## 2. 标准制作链

1. **语义盘点**：逐页标注说明、要求、素材、案例、待修改页、结果页和交付页；锁定文字、图片、Logo、字体、数据、动画和编辑性要求。
2. **来源、权限与素材缺口**：为每项内容记录来源；参考图只定义构图和视觉目标，除非明确授权，不复用其像素。完成 deck plan 后登记真实素材缺口，本地不足时联网检索有明确许可证的候选，并把选中素材、用途、页面、来源、授权和哈希保存在当前 Work 的 asset plan/ledger。
3. **选择生产路线**：原生创建、模板继承、截图重建或视觉候选只能选一个主路线；image-first 候选不得标成可编辑母稿。
4. **建立白名单**：明确允许变化的页、对象和属性；未列入白名单的内容保持不变。
5. **先静态后动态**：先让无动画页面成立，再添加 PowerPoint 原生时间轴、Morph 或轮播。
6. **视觉前处理**：图片进入页面前检查抠图、等比裁切、蒙版、异形边界、色调统一和主体安全区。
7. **结构复核**：检查母版、版式、主题、design 绑定、全局 ID、对象层级、字体、动画、来源注释和可编辑性；备注只保留演讲讲稿，不得出现本地路径或 `[Sources]` 来源块。
8. **全尺寸视觉 QA**：逐页导出后检查几何、方向、间距、裁切、亮度、文字换行、关系和视觉重心；对照参考后继续迭代。
9. **桌面运行 QA**：真实 PowerPoint 打开、保存、关闭、重开和导出；用户要求动态交付时同时保留效果清单，并用 PowerPoint 影片的同页早晚关键帧确认真实播放变化，复杂动画再增加更密集的逐帧证据。
10. **交付**：保留提供素材、持续使用的制作代码/配置、成品和一份必要校验收据；可重复生成的图像用于运行期自审。通用经验写入共享代码或简短规则，不复制聊天或重复报告。

## 3. 高频失败模式

- **结构通过但画面不像**：对象数量、页数和 PPTX 可解压不能替代全尺寸视觉比较。
- **参考复刻变成整页位图**：应重建文字、图片、形状、表格和图表；若只能 image-first，必须明确不可编辑。
- **内容关系被卡片化**：流程、路径、层级、时间和因果需要保留，不能只追求整齐。
- **硬分割与主体变形**：用渐变蒙版、重叠、斜面或异形裁切处理边界；图片始终保持宽高比。
- **动画“有名字、没效果”**：验证启动方式、时长、路径、对象身份、循环闭合和重开持久化。
- **模板主题漂移**：比较主题部件，保持 master -> layout -> slide 继承链，不另做一套平行设计覆盖模板。
- **工具报告误导**：Office schema 警告、COM 启动错误和预览缓存需要结合 ZIP/XML、实际对象变化及桌面 PowerPoint 结果判断。
- **备注泄露内部路径**：来源位置和素材路径应保存在证据账本、`source-notes.txt`、构建清单与 QA 记录中；PowerPoint 备注只面向演讲者，不写任务目录、本地绝对路径、`file://` 或 `[Sources]` 来源块。
- **用同一图片或同一容器统一全稿**：重复背景图、重复白色卡片和相同章节节点会形成模板套页感。统一字体、色彩、标题基准与图片色调，同时让页面轮廓和素材跟随内容变化。
- **明确视觉禁令只靠主观检查**：把“不要白框”“不要整页图片蒙版”等反馈转换为对象级扫描，检查目标页的几何、填充和图片覆盖范围。
- **单页修订影响其他页面**：保存修改前渲染，对非目标页执行图片哈希或像素对照；只有目标页发生变化时才交付。
- **低龄科普封面或结束页因蒙层变暗**：大面积深色蒙层虽然提高白字对比度，却会削弱儿童感并让文字与人物争抢焦点；优先改为明亮底色下的独立文字区与插画卡片，保留清楚的主体安全区。
- **连接器与独立箭头叠加**：连接器再叠加带箭杆的 `rightArrow` 会被读成两条关系；长距离流程使用连接器的单一目标端箭头，短距离流程使用单一箭头形状。端点必须落到主体可见轮廓，并在桌面 PowerPoint 导出图中检查实际路由。

## 7. 商品供货与销售型方案

- 供货宣传方案优先按购买决策组织：优势与可信度 → 供货品类 → 具体货品与实景 → 包装款式 → 专属定制 → 服务保障 → 联系或下单入口。不要因图片数量多而把叙事退化成重复图册。
- 商品图前处理的第一目标是内容保真。生成式抠图可能在视觉上更干净，却会改写包装文字、重排商品或改变数量；真实商品方案应使用像素保真的透明分割，并保存包装完整性验证，失败时回退到完整照片。
- 浅色包装、白色标签和透明塑料边缘容易被背景移除算法误删。检查显著像素保留、边缘与全尺寸渲染；不要把透明面积、模型成功状态或文件可打开当成商品完整性的证据。
- 圆盘、礼盒套装等整体陈列必须完整呈现。辅助缩略图也不能只留下主体一角；若容器比例不匹配，应扩大、改为接近正方形或重新组织信息区。

## 9. 模板结构索引与设计语言

- Work 56 的结构索引覆盖 1,364 个 PPTX（均完成解析）、32,787 页记录和 181 个分类，解析错误为 0。覆盖范围表示 OOXML 字段已提取，不表示全库页面已视觉检查。主题颜色读取可能漏掉自定义形状、母版及图像色；字体值可能受未解析的母版继承影响；标题/正文角色是启发式信号；文字不完整输出，图片语义、页面质量和事实正确性不能由此确定。
- 新建竞赛、答辩、工作汇报等作品时，按“场合 + 页面功能”检索：先从本任务的大纲提取每页角色，再查询如“竞赛 + 论点/证据”“年度汇报 + 目标/实际对比”，最后追加风格偏好。先比较 2–5 个相关候选的实际整页与邻页，再决定借鉴主题/母版、特定版式或构图关系；颜色相似和目录命中都不足以选定整套模板。
- 把设计输出分为两种用途：`advisory` 观察（构图经验、语言规则、图像角色和受限测量说明）提供规划建议；经全页视觉核验、含受控数值 `design_tokens` 的记录才可能作为新创作基线。规划器按场合、页型和风格选择，渲染阶段重新校验来源 PPTX 的 SHA-256；文件已变更或缺失时应抑制 token。只有实际可见并检查过的页码属于审阅范围，不能扩写成整套模板的质量结论。
- Studio 在 `planning/template-design-candidates.json` 记录宽泛候选，在 `planning/template-design-language.json` 的 `slide_guidance` 按当前页型给出经过来源哈希重验的具体页面、构图、语言规则、图像角色及 OOXML 数值依据。作者应按当前页主张与证据选用或舍弃建议，再看首稿整页修正。独立查询可运行 `python3 scripts/with-studio-runtime.py --work-dir work/<N> -- python scripts/search-templates.py design-language --workspace . --form competition_defense --pattern cover --pattern editorial_columns --style 竞赛`；汇报用 `business_report` 与 `structured_rows`、`comparison` 等当前页型。特殊海报/章节页可用其 catalog `page_variant` 同名模式查询，但不自动套入 16:9 作品。
- 缺字或字体回退的渲染只允许记录可见构图的有限观察，不能据此声称中文字体、字级层次或文字适配已验证。无论观察还是 token，都不授权复制来源模板的事实、文案和数字；图片、矢量图、Logo 等素材须逐项核对含义、视觉适配与权利状态，并通过当前 Work 的绑定账本进入成稿。若没有匹配且可复核的候选，按当前内容新建并记录原因。

## 10. 深索引、可执行复用与内容命名（Work 60）

- `模板库/DEEP-INDEX.jsonl` 是按 PPTX 当前可见页读取的机器结构索引：标题及置信度、正文摘录、页面功能、构图对象数和区域、字级层次、图片/SVG 关系与媒体哈希。它给出具体源页和对象位置，不能代替看整页，也不能凭周围文字断定图片实际含义。索引只对文件大小、修改时间、解析器版本与预期源哈希一致的记录复用；选中时仍应重验源文件 SHA-256。
- 新建业务或详细需求先形成本任务受众、场合、逐页主张与证据；规划器随后写 `planning/library-reuse-candidates.json`。`library-reuse <job-id>` 以场合为整套模板硬边界，分别排序整套模板与素材候选。分数列出内容、主题、页型、构图、层次及邻页顺序；文件名不参加匹配。整套来源若有显著异域主题，其嵌入素材候选也降权并提示冲突，仍须看图才能确认单张素材的真实含义。竞赛答辩不能因为同样谈“服务方案”就采用普通工作汇报模板。
- 整套模板经真实页检查后通过 `library-template` 绑定，沿既有页级套用证明与成品门禁；即使请求只写“新建 PPT”，也可在当前逐页候选生成后、原型通过前把候选提升为正式模板路线，旧新稿计划随路线变更失效，重新编制模板页映射。单张实际嵌入的图片或 SVG 经源页、shape、含义与权利状态检查后，通过 `library-media` 复制到 Work，记录源 PPTX/源 SHA/页号/shape/媒体哈希/当前页用途，并在 DeckPlan 放入 `library:<id>`。调用方须提供非空 `--selection-note`、`--rights-handling-note` 及 `--task-reuse-authorized`；这些是本次任务的选择和授权记录，不会把目录里的 `unverified` 权利提升为已验证许可。仅由原生形状构成的图示列入 `source_page_candidates` 供整页研读，不冒充可直接复制的图片素材。HTML 渲染时对账本文件再次验哈希，原生/最终 PPTX 仍须看实际输出页。检索命中、复制到 Work 和可见成稿使用是三种不同状态。对新建稿，若已检出候选而既未绑定任何库内资产，也没有按具体源页记录不适用原因，原型构建会被阻止；例外由 `library-reuse-decision <job-id> --request <json>` 记录并绑定当前计划和候选清单哈希，不另向用户索取确认。
- 数字、时间戳或哈希文件名的批量重命名先由 `library-name-plan` 形成含当前源大小、修改时间和预期哈希的计划；优先采用第一可见页高置信标题占位符或经严格过滤的封面大字标题，其余只能明确标为分类来源，不把正文里的 KPI 句子误当整套名称。重名时仅以高置信早期正文页标题区分已确认的封面主题；分类回退或任意正文摘录不能充当内容区分词。应用时同步更新活跃目录、设计索引、展示名称和旧路径别名，保留 Work 内备份及回滚清单。多个同类模板若只能靠哈希尾码区分，保留候选等待逐页核对，不为追求重命名数量而制造伪语义。

## 11. 动态模板的层级、检索与复制（2026-10-07）

- 动态效果不一定写在单张幻灯片的 `ppt/slides/slideN.xml`。镶金边集合的 SS57 横向循环、SS62 照片摩天轮把核心路径/旋转时间轴写在所关联的 `ppt/slideLayouts`；只扫描页自身会把这些模板误判为只有音乐或完全静态。检索和分析必须沿当前 slide→layout→master 关系看对象与时序，并分清页面转场、对象行为及音视频控制。
- 平滑切换是跨相邻页的关系。SS43 花瓣从收拢到展开依靠第 2 页的 Morph；SS63 的 16 图拼心依靠连续多页状态。单独拿终态页、主题色或一张静帧都不能复制其动态表达。路径循环还要核对照片数量、版式槽位、首尾闭合和重复时长；媒体型开场要核对视频、蒙版、标题与播放命令的时序。
- `模板库/镶金边高端动态ppt/分析索引/` 把 126 份 PPTX 的 1,303 页保存为逐份源 SHA 绑定的结构、逐页报告和有限静态预览。动态请求先由 `library-reuse` 合并普通场合/内容检索与 `library-motion-search` 的动画候选，再用 `library-motion-inspect` 读具体源页和相邻页。目录分类为页级素材的结果只证明动效来源，不能把文化旅游或人物示例直接当作竞赛整稿。
- 真正借用时，用 `library-motion-copy` 保留连续源页、关联版式/母版和原生时间树，对明示的 shape ID、原文字/媒体 SHA 做白名单替换；`COPY-SMOKE.md` 记录了真实两页图文轮播模板的共享照片槽位替换。保真回读证明 OOXML 时序未丢，仍须检查实际页面与 PowerPoint 放映；供应商示例事实、图片、Logo、水印和未核实媒体权利不直接迁入客户作品。

## 12. 创赛与职业规划模板类型匹配（2026-10-07）

- 新建创赛稿前区分创新创业/科技路演、研究调查、乡村/红旅/非遗实践与通用框架；职业规划稿区分成长发展、就业能力论证、竞赛展示、访谈和课程材料。类型决定论证页序，目录分类和主题色只帮助发现候选。细节及代表源页见 创赛学习总结（本地资源，未随公开仓库提供） 与 职规学习总结（本地资源，未随公开仓库提供）。
- 创赛库有 24 份/72 页 PPTX 近似静态视觉样本，旧 PPT 转换件只有近似结构；职规库视觉样本为 20 份/60 页，另有 240 条旧 PPT 路径的近似结构摘要。两者的 STYLE-CATALOG/STYLE-PAGES 机器索引不能表示全库视觉审阅。检索后必须重验当前源 SHA、`pptx-inspect` 真正源文件、预览实际源页，再通过 source-preserving copy 保留母版/版式/主题/对象关系，按白名单替换内容并检查替换后整页与邻页。
- 这两套视觉联系表/OfficeKit 预览是近似静帧。OOXML 或静帧不能证明 PowerPoint 原生显示、复杂字体/母版、媒体权利、事实有效性或动画播放。将静态渲染、结构、原生打开/放映分开记录；每个具体项目重新核验图片意义、人物信息、数据来源和授权。

## 13. 整套模板套用与少数页面换版（2026-10-08）

- 新项目先按听众、赛事/业务类型、逐页主张和证据选 **一份整套主模板**。`library-hybrid-plan` 给出来源 SHA、页型与视觉差距；助手还需看真实封面和实质内容页，再决定主稿。内容替换按输出页/对象 ID 和原文字或媒体 SHA 绑定；来源事实、图片和占位项要逐页核对。`library-hybrid-build` 默认复制主模板全部页并保持其页面顺序和未改部分字节，输出是可编辑候选，不自动成为客户成品。
- 只有客户要求局部换版时，才用 `library-style-page-search` 按该页的主张、角色、需要的证据和构图检索替代页。优先同类来源与相近色字层级；跨库页必须是真正功能相符的版式参考，旧事实和媒体全部重新映射。所选来源页要与被替换的主稿页分别预览；组合请求记录目标页号、供体页号、两个原件 SHA、视觉观察、版式匹配及配色/尺寸处理。默认最多两页，防止一整稿拼成没有统一结构的素材合集。
- 已填写案例可以成为 `layout_only_reference`：先确认它与当前目标页具有相同功能和明确相符的职业/业务主题，再检查可编辑对象与画布尺寸。执行时每条旧文字、每张图片须替换或逐项说明为什么保留；继承的版式/母版图片和文案也要审阅。图表、表格、SmartArt 等旧数据若无法逐项重建，当前合成器会拒绝直接迁入。内部护理案例的 16:9 环形行动计划页以三处文字替换和一处结构序号保留完成映射，蓝灰重映射后实际页图可读；其余主稿旧事实仍是待处理内容。
- 静态跨源合成只迁移供体页和它的布局/母版/主题/媒体依赖，并回读关系与内容类型。主包其它页保留原字节。普通原页转场可以保留；Morph、复杂触发、媒体控制或不安全依赖会被阻断。仅在任务明确要静态版式时可显式剥离供体本页安全对象动画，回执记载被移除的时间节点；画布只容许有记录的微小差异，不隐式缩放。导入页颜色可依据主稿实际配色显式映射，不能由主题色名称推断视觉已协调。
- 文字多 run 替换保留首段样式；共享图片用 copy-on-write 仅改变目标对象的媒体关系。若旧媒体仍被别页使用，回执报告剩余消费者和待清理范围。图片可能藏在普通形状的位图填充、版式或母版层；先看对象层、几何和真实整页，再绑定图片 ID，不能把铺满全页的背景误认作头像。输出 `content_audit` 与 `unmapped_changed_page_content` 仅提示仍需审查的旧文案/素材。替换后的目标页及前后页必须实际看图，最终仍按当前 Work 的表达、原生与交付边界执行。
