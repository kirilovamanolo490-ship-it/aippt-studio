# AI PPT 作业与迭代经验

本文只保留会改变后续决策的经验。八节作业的代表制作过程见 [ppt-production-knowledge-base.md](ppt-production-knowledge-base.md)，案例来源和清理后的证据位置见 [evidence-index.md](evidence-index.md)。

## 1. 先建立任务语义图

在制作前逐页标注：`说明`、`要求`、`素材`、`案例/参考`、`待修改页`、`结果页`、`交付页`。同时记录：

- 该页是否必须原样保留；
- 结果应插在什么位置；
- 哪些文字、图片、Logo、字体、数据和动画被锁定；
- 对象应位于页面、版式还是母版；
- 用户要求的是可编辑稿、视觉样稿，还是两者都要。

不得用奇偶页、固定间隔或文件名猜测页面角色。必须结合页内文字、相邻页说明和案例关系判断，并保存依据。原稿默认不覆盖；若课程要求“保留原稿及成品”，采用“要求/素材/案例 -> 新增结果页”的顺序。

## 2. 参考资料的边界

- 用户提供的参考图或参考 PPT 默认只定义构图、层级、节奏和视觉目标，不授权复制、嵌入、描摹或裁切参考像素。
- 用户提供的照片、Logo、数据和文字是内容源；不要用生成内容替换官方素材，也不要补造身份、奖项、学校、专家或业务数字。
- 跟随模板时继承其母版、版式、主题、字体层级和命名对象；编辑继承对象，不要另做一套平行设计盖在模板上。
- 如果为了快速候选而使用整页图片，必须标记为 image-first/不可编辑候选。课程要求可编辑时，应重建为原生文字、形状、图片、表格或图表。

## 3. 失败到修正的通用模式

| 失败表现 | 常见根因 | 正确修正 |
| --- | --- | --- |
| 在错误页面作答，或把作业说明留在成品页 | 未区分说明、素材、案例和结果 | 先建逐页语义映射；复制正确的待修改页；最终页写给观看者，不暴露作业脚手架 |
| 文件结构通过，但视觉仍明显不像 | 只检查对象存在、页数或包结构 | 导出每页全尺寸图，与要求/参考并排检查几何、方向、间距、裁切、厚度、亮度和层级，修改后重新检查 |
| 看似复刻参考，实际只有一张全屏图 | 把参考像素当成交付物 | 使用来源对象和原生元素重建；检查普通文字、图片、表格和图表能否继续编辑 |
| 页面被做成一堆卡片，原有流程关系消失 | 只追求整齐，没有保存语义关系 | 保留路径、时间线、因果、层级、对象身份和阅读动线；优先做一个连续构图 |
| 色块与照片像两个硬拼矩形 | 缺少边界处理 | 根据主体位置使用渐变蒙版、斜面、重叠、异形裁切或低透明度复用，避免突兀竖切 |
| 人物或主体拉伸、白底明显、关键部位被裁掉 | 未做视觉前处理 | 先判断抠图、蒙版、裁切和色调统一；保持原始宽高比并在全尺寸渲染中检查主体 |
| “立体图片”只是斜排，方向和侧面互相打架 | 各面板独立调整，没有共享空间模型 | 先定义统一汇聚方向、基线、深度向量、遮挡和光源，再统一侧面亮度；中心主体承担焦点 |
| 动画对象存在但效果不成立 | 静态布局和时间轴混做，或只有动画名称没有因果 | 先完成无动画也成立的静态页，再用 PowerPoint 原生时间轴添加效果；验证启动方式、时长、路径、对象身份和循环闭合 |
| Morph 看起来跳变 | 相邻页不是同一对象 | 复制原页保留对象身份；必要时为对应对象设置一致名称，再改变位置、尺寸和裁切 |
| PPTX 可解压且 Office 校验通过，PowerPoint 仍报错 | PowerPoint 专有结构约束未覆盖 | 对所有 master/layout ID 做全局唯一审计，并在桌面 PowerPoint 中打开、保存、关闭、重新打开和导出 |
| 模板导入导出后视觉或主题漂移 | 主题部件、继承关系或对象层级被重写 | 比较主题部件哈希；必要时恢复原主题；复查母版、版式、页面绑定和继承对象 |
| 指定字体在别处打开后变样 | 用文件名猜 family、字体未安装或发生静默回退 | 读取内部 family name，检查授权和安装状态；逐对象替换并重新渲染；保留字体来源说明 |
| 工具返回“成功”，但画面没有变化 | 批次整体回滚、截图缓存或 SVG 未重新解析 | 检查真实 created/updated 节点和导出文件；换节点或等待缓存；必要时删除并重新插入 SVG frame |
| 流程图出现“线条 + 重复小箭头”、方向翻转或箭头与主体有空档 | 同时使用连接器和独立带箭杆的箭头形状，或端点按透明图片外框而不是可见轮廓落位 | 一个关系只保留一个箭头对象：长距离用连接器自身的目标端箭头，短距离用单一箭头形状；端点锚到可见轮廓，并以桌面 PowerPoint 导出图检查方向、空档与重复。 |

## 4. 已验证的工具与错误辨别

- PowerPoint `0x80070570` 在本工作区曾由重复的 `sldLayoutId` 引起；它是文档解析错误。`0x80070520` 则发生在无交互桌面会话的 COM 启动阶段，不能据此判断 PPTX 损坏。
- 普通 ZIP/XML、`python-pptx` 和 Office schema 校验不能替代真实 PowerPoint。
- 反过来，PowerPoint 能打开或完成导出，也不能替代 Office schema 校验。富文本生成稿若报告重复段落属性或部件子元素顺序错误，应定位到具体 XML；仅在重复属性完全一致时去重，存在冲突时不得直接删除。修复后重新通过结构校验和原生渲染，不把所有校验错误都归为工具兼容性。
- Artifact Tool 的某次 `addBox` 路径触发 `TypeError: e.trim is not a function`；遇到类似错误应缩小到具体属性和值，不要把整段压缩库堆栈当成根因。
- Ardot 的 `NO_ADAPTER` 会使整批编辑回滚；必须看到实际创建/更新节点。其截图可能短时缓存，SVG 更新也可能不重新解析旧子节点。
- 某些 SVG 渲染器不能稳定显示 `stroke-dasharray`；对关键环形图可使用明确的 SVG arc path，并以最终渲染为准。
- 一次轮播脚本失败是目标 PPTX 被其他进程占用；写入前应使用新输出路径或确认文件锁，不能把占用错误误判为动画逻辑错误。

## 5. 视觉决策优先级

1. 用户本轮明确反馈；
2. 作业要求和指定素材；
3. 用户指定的参考或模板；
4. 本文沉淀的稳定偏好；
5. 一般设计习惯。

本工作区已验证的偏好：

- 成品页应面向观众；当用户要求正式成品时，去掉作业编号、导航标签、教学说明和占位文字。
- 优先放大主标题、减少低价值文案、建立单一视觉重心；不要把页面平均切成许多 UI 卡片。
- 不添加未要求的额外页面、动画、反射、装饰或重复素材。
- 自定义电影感封面应使用一个连贯的主视觉，而不是多个互相竞争的图片区。
- 面向小学低年级的明亮科普课件，封面和结束页应优先把大标题、课堂信息与人物插画放在独立区域。除非用户明确要求沉浸式全图，不用大面积深色蒙层换取白字对比度，也不让文字压在人物脸部、动作或关键道具上。
- 数据页只使用来源数据，保留可追溯映射；远距离阅读时标题、数字和结论必须足够大。

### 五图立体画廊的本地默认

当用户提供五张照片和单独视觉参考时：

- 只使用提供的五张照片；一张可编辑幻灯片；五个站立面板；
- 面板共享同一汇聚方向、统一照片派生侧面深度和基线；
- 侧面压暗，不能使用突兀的纯色亮块；
- 以中央或用户指定面板为焦点；
- 默认不增加独立倒影行。教程中出现倒影不代表本用户需要倒影，除非本轮明确提出；
- 完成标准是全尺寸视觉比对通过，不是“PPTX 能打开”。

## 6. 动画与交互

- 光效擦除：光的运动与文字擦除必须在时间轴上同步，形成“光扫过 -> 文字变化”的因果。
- 循环轮播：尺寸、位置、路径距离、线性速度、进入/退出和回到首帧必须共同闭合；只看起始 PNG 不足以验收。
- 多状态轮播若使用整页状态图，应明确可编辑性损失；优先评估独立图片和原生对象方案。
- 最终至少保留 PowerPoint 重新打开后的效果清单；复杂动画应额外导出短视频或逐帧证据。
- 即使是常规淡入、擦除和强调动画，只要它是用户要求的交付能力，也应在 PowerPoint 影片中比较同一页的早、晚关键帧，确认对象确实从初始状态变为完整状态；OOXML timing 节点只证明动画被写入，不能单独证明播放成立。

## 7. 交付门禁

交付前同时通过以下三层：

1. **语义与视觉**：页序正确；来源内容完整；全尺寸逐页检查；无新增重叠、裁切、占位符、乱码或低质量图片。
2. **结构与可编辑性**：页数、母版、版式、主题、全局 ID、字体、对象层级、动画、来源注释和编辑能力符合要求。
3. **桌面运行**：PowerPoint 打开、保存、关闭、重开、导出成功；动画或 Morph 在真实播放环境中成立。

自动溢出报告必须区分“原模板继承且故意越界”与“本轮新增缺陷”。只有与未编辑 starter 对照一致并经视觉确认，才能把警告记为继承例外。

## 8. 明确视觉禁令与局部修订 QA

- 不要用同一张背景图或同一类容器承担整套 PPT 的统一性。统一性应优先来自字体、色彩、标题基准和图片色调；页面轮廓与素材应随内容任务变化。
- 当用户明确禁止某类视觉对象，例如白色卡片、浅色节点或整页图片蒙版时，应把禁令转换为可扫描的对象级条件，检查目标页的几何类型、填充颜色和图片覆盖范围，而不只依赖肉眼判断。
- 用户要求只修改一页时，应保存修改前渲染，并对非目标页执行图片哈希或像素对照，证明修改没有扩散。
- 用户认可局部样稿后要求扩展完整稿时，已认可页也是保真范围。使用同一应用、相同分辨率比较扩展前后的原生渲染；发现像素差异须解释或修正，不能只比较页数与文字内容。
- 字号、加粗与重点色是独立验收项。针对用户明确要求的粗体或标红，应检查相应文本run的实际字号、bold和颜色，再结合PowerPoint渲染确认字体回退和视觉粗细；对象属性存在不等于视觉效果达标。
- 图片作为内容素材时，先根据主体安全区和原始宽高比选择横向或竖向板块；除非场景确实需要沉浸式封面，不默认把照片铺满整页再加蒙版。

## 9. 商品包装图的完整性门槛

- 商品包装、食品、礼盒和套装照片属于高保真内容。抠图前后必须核对商品数量、包装文字、Logo、边缘、方向和整体轮廓；背景更干净不能抵消包装受损。
- 生成式图像编辑若重排商品、改写标签、改变包装结构或补造细节，立即淘汰，不得进入真实供货、产品目录或销售方案。浅色包装与白底难以可靠分割时，优先使用完整增强照片。
- 圆盘、礼盒套装和整组陈列是一个完整视觉对象。主图与辅助图都应保留完整外轮廓；如果狭窄容器只能显示一小截，应重排版式，而不是裁掉商品主体。只有明确标记为“细节特写”时才允许局部裁切。
- 商品方向以包装正面文字为判断依据。拍摄方向不等于展示方向；放入页面前应先旋正，再决定裁切、抠图或完整照片方案。

## 10. 现场证据、语义断行与正式名称

- 设备或车间照片承担事实说明时，采用“一图一身份一说明”。设备近景与环境全景分别建立独立信息单元，标题数量和图片数量必须逐一对应；卡片轮廓应适配原始宽高比，不以强制横裁换取表面整齐。
- 验证计划、排期或设备清单中的长条目，应先解析项目名称、括号规格、执行阶段和元数据。项目名称与安装调试、IQ、OQ、PQ 等阶段保留在主行，括号规格使用较小字号的第二行，计划日期、工期、责任人落在统一的元数据基线；不要按字符数机械断行。
- 用户确认的品牌、设备、机构等正式名称，必须写回持续使用的构建源，并在最终成品执行旧名称残留扫描。只修改一次性交付文件会在后续重建时产生名称回退。
