# 页面表达选择：先确定每页的信息关系，再选排版

适用范围：新建内容、且需要新建视觉系统的 `NEW_COMPOSITION + CREATE_NEW` 路线。保留现有 PPT、按模板美化、参考重建和局部微调都以原稿、模板、用户明确的参考及冻结页为准；这里的默认模式不能替它们换版。页数为一或二时，直接安排真实内容，不自动凑封面、目录或结语。

Studio 在 `planning/deck-plan.json` 的 `planning_strategy.expression_plan` 保存每页所选模式、理由、可见来源要点数和素材数。它从页面角色、实际文案和图片引用选择排版。标题已经完整说出首条来源文字时，正文不再重复该句；仅有一个新的正文论点时可使用主张页。只有文案明确提出比较或先后关系时，才使用双栏对比或流程。两三条独立要点可在宽阔的编辑式分栏中并列，不能把它们改写成并不存在的因果关系。图片页可交替安排图文左右位置，图像仍保持真实矩形边界或明确绑定的裁切/蒙版，不能把直角图片生硬叠在圆角、椭圆装饰框上。

| 模式 | 来源条件 | 页面任务 |
| --- | --- | --- |
| `cover` / `overview` / `closing` | 规划中已有相应且有依据的角色 | 开场、说明叙事、收束已给出的结论 |
| `statement` | 一条不同于标题的明确论点 | 用一个主张占据页面中心，不用小字填空 |
| `comparison` | 两项资料且文案明确对比 | 两边保持等权，保留真实比较对象 |
| `sequence` | 原文有步骤、阶段或先后 | 按原顺序阅读，不添加假编号 |
| `editorial_columns` | 两三条并列来源要点 | 分栏表达，使用线和留白，不堆通用卡片 |
| `image_right` / `image_left` | 页面已绑定来源图片 | 图片和正文相互解释；连续图片页交替重心 |
| `cinematic_still` | 本轮明确要求电影感，且当前页有一张真实图片、最多一条新论点 | 封面或内容页改为大幅完整画面与紧凑文字区；图像 `contain`，不自动裁主体、不加圆角外框 |
| `structured_rows` | 关系不足或事实较多 | 保持来源顺序，允许 QA 要求拆页 |

电影感是明确的视觉方向，不是自动给所有竞赛或品牌稿套暗色。`cinematic_still` 已接到 HTML 首稿渲染；一套初稿只自动选一页大画面主镜头，后续有图页仍根据图文关系改变版式，避免重复同一片头构图。它不会伪造图片或为缺素材的页面套黑底。规划中的 `cinematic_visual_gap` 会暴露“用户要电影感，但尚无适合单一焦点的来源视觉”的缺口，后续须用已授权素材补齐或改选表达。该静帧构图不等于电影式动效或视频。要做运动表达，应先确定跨页同一对象与相邻镜头的关系，再分别验证原生 PowerPoint 放映和连续影片帧。Microsoft 当前的 Mac 导出说明指出，对象动画不会进入导出的影片，部分转场也可能不同；用户要的是成片动效时，必须使用能产生目标动态画面的制作和导出路线，不能把「PPTX 有动画」与「MP4 有动画」混成一次验收。

这些只是可复核的首稿构图，不是审美通过规则。浏览器溢出检测、当前页和相邻页整页审阅、原生 PowerPoint 检查依然分层执行。图片内容是否真的支撑文案、字号与留白的比例、边缘是否相撞，以及演讲文字是否正式，仍要看真实页面。小修订使用现有来源哈希绑定的对象级修订和改动页预览，不重新规划全稿。`expression_plan` 仅是排版建议，不能替代作品集的视觉审阅记录或当前用户需求。

当前模板与完成案例均按作品场合和主题直接放在 `模板库/` 下，由根级 `模板库/CATALOG.jsonl` 和 `模板库/CONTENT-CURATION.jsonl` 提供哈希绑定的检索标签；清单中列出的演示文件不再重复加入 Work 启动索引。完成案例仍可作结构参考，但不再以 `作品集` 来源目录分类。检索结果只是候选，需继续查看实际页面、版式和素材条件；案例中的客户事实与图片不会自动成为新项目证据。字体包独立存放且不参与幻灯片检索。Work 54 曾使用 `模板库/PPT模板/全部典藏合集`，该路径仅用于解释当时迁移记录。

Work37 的作品集页面表达抽查（本地资源，未随公开仓库提供）从三份成品和两份模板各取四页，共观察 20 页。可提取的是“竞赛封面的项目识别”“调查发现的证据—解释”“真实流程的先后”“汇报正文随图表、表格、事项变形”等信息关系；小字过密、重复卡片、没有导航作用的编号和口径不明的图表同时被记为反例。抽查图来自 OfficeCLI 的近似渲染，不能替代原生 PowerPoint 的页面验收，也不能证明整份作品已经成为可直接套用的模板。

这批抽查现在有一个本地、人工审阅的页面表达案例目录（本地资源，未随公开仓库提供）。仅新建视觉系统的规划会按用途和页面信息结构挑选候选，逐文件校验原 PPTX 的 SHA-256，并把结果写入 Work 内 `planning/portfolio-expression-examples.json`；deck plan 只存候选 ID 和路径。来源改变或文件不在本工作台时，候选自动失效。目录同时保存可借鉴的构图关系和必须检查的反例，选中案例不等于自动套版、复制图片或证明当前页面已达标。一个页型没有相关案例时允许为空，不用无关模板填补。原“商业案例模板15页”实际是党政与医疗财政工作总结，案例目录已更正为公共财政构成关系参考，不能作为商业计划案例。

外部参照：[Microsoft Designer 的自定义模板建议](https://support.microsoft.com/en-us/powerpoint/creating-custom-templates-that-work-well-with-designer-in-powerpoint)要求按标题、内容、对比、图文等真实信息形态提供不同版式并用真实文案检查；[PowerPoint 母版说明](https://support.microsoft.com/en-us/powerpoint/training/what-is-a-slide-master-in-powerpoint)也把版式和内容类型关联。Studio 将这种“先看信息形态”的思想实现为本地、可见的表达选择，未声称调用 Microsoft Designer 或自动获得其排版质量。

Work37 的外部设计站点初核（本地资源，未随公开仓库提供）列出花瓣、站酷、Fotor、Office Plus 等参考入口、具体作品线索及各站可确认的下载/授权边界。站酷原作者文章里的景深、光影、色调提示已转成上面的焦点与图像关系判断；其他作品页目前只能看到站内索引说明，尚未逐套下载模板或逐帧审片，所以不构成作品质量证明。动效能力边界以 [Microsoft 的 Mac 动画说明](https://support.microsoft.com/en-us/powerpoint/training/animate-text-or-objects)和[Mac 视频导出说明](https://support.microsoft.com/en-au/powerpoint/save-a-presentation-as-a-movie-file-or-mp4-in-powerpoint-for-mac)为准；两种输出都需要真实播放复核。
