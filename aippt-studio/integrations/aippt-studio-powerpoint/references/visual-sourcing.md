# Visual sourcing for presentations

Use this reference when a page needs a photograph, illustration, background, map, diagram, icon, or other visual. Start with the page's message and the image's job; a beautiful image with the wrong subject or meaning weakens the presentation.

## Decide whether to use supplied, searched, generated, or editable visuals

| Visual need | Preferred path | Reason |
| --- | --- | --- |
| The user's product, people, event, site, document, or work | Supplied original or an authorized, identifiable real-source image. | Identity and factual fidelity matter more than polish. |
| A factual or historical claim, data, map, legal or official context | Verified source image, data visualization, or editable diagram with traceable source. | A generated scene cannot prove a real fact. |
| A process, mechanism, comparison, or hierarchy | Editable shapes, diagram, chart, or source-grounded illustration. | The relationships must stay accurate and legible. |
| An atmosphere, metaphor, scene-setting opener, or non-factual conceptual explanation | Carefully chosen licensed/approved image or generated illustration. | The visual supports tone without pretending to be evidence. |
| No visual clarifies the message | Deliberate text, data, or open space. | An image is not required on every page. |

Treat a general request to beautify a deck or create a visual presentation as permission to **look for relevant visual candidates** within the current surface, unless the user says to use only supplied material or a source/rights boundary forbids additions. It does not authorize inventing claims, replacing real client visuals, disclosing private material to a search service, or using a connected app outside its visible permissions. When the user explicitly requests web research or image generation, pursue it when the current host exposes that capability; do not repeatedly ask for the same generic preference.

## Search for real visuals

1. Name the needed visual in terms of subject, page claim, audience, aspect ratio, and desired composition. Search that specific subject instead of a broad aesthetic word.
2. Use web search, image search, or an approved connected source only when actually available in the current PowerPoint task. Search access in another ChatGPT surface does not prove access inside PowerPoint.
3. Prefer official, primary, or identifiable sources for real people, places, events, products, logos, maps, and public institutions. Check whether the image really depicts the intended subject, date, version, and place.
4. Check usable resolution, aspect ratio, crop safety, embedded text, watermarks, duplicate use, and relevant usage terms. Keep the source URL or attribution in the task's external asset record when the host permits; never paste a raw URL or asset path into presenter notes just to satisfy provenance.
5. Select a small set of distinct candidates for the same visual role, compare their meaning and geometry, then use the one that works on the actual page. Do not fill a deck with unrelated search results or repeat one hero image on every slide.

For design inspiration and downloadable presentation templates, separate observation from asset reuse. A free-to-view gallery can teach image scale, title placement, scene progression, and transition rhythm without granting permission to copy its images or distribute its editable deck. Before using a downloaded template or media in a client result, inspect that exact item's author, license, attribution, commercial-use limits, editability, and the rights of embedded photos or fonts. If these terms are unclear, study the design relationship and use independently authorized assets for the current work.

If the current surface can search but cannot insert or retain the chosen image, give a concise asset recommendation and identify the missing operation. Do not claim that an image was placed.

## Generate an illustration when appropriate

Use image generation for conceptual or editorial roles when a sourced real image is missing, visually unsuitable, or less clear. The prompt should describe the exact subject, audience, presentation form, page role, visual focus, composition, aspect ratio, subject-safe space, palette relationship, and excluded artifacts. Do not include customer-sensitive source passages when a generic visual description is sufficient.

Inspect the generated result before insertion: subject identity, anatomy and object integrity, embedded words, cultural or institutional symbols, cropping, color balance, and whether it visually supports the intended claim. Revise or reject an inaccurate image. Generated illustrations must not impersonate documentary photographs, real product packaging, official facilities, specific people, a historical record, or measured results. For a real entity or event, use a verified source image or an explicitly illustrative treatment that cannot be confused with evidence.

If image generation is unavailable in the current PowerPoint host, produce a precise visual brief or use a verified supplied/search asset. A skill instruction cannot add a missing tool to the host.

## Place and review the visual

- Match the visible image edge to its actual crop, mask, border, and backing. A rounded background behind a rectangular image does not make the image rounded.
- Preserve subject-safe areas, faces, labels, document edges, and quantitative details. Choose a different composition if necessary rather than hiding the evidence.
- Check the final slide at presentation scale: hierarchy, text contrast, image-to-claim relevance, accidental overlap, repeated visual motifs, and continuity with adjacent slides.
- Keep sourced images, generated illustrations, and data figures distinguishable in the task's external evidence or asset record. Only make a user-facing claim about search, generation, placement, or rights review when that step actually happened.
